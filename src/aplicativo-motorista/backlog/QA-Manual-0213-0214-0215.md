## Como usar este roteiro

Cada caso de teste tem:
- **Pré-condição**: estado mínimo para o teste funcionar
- **Passos**: ações em ordem
- **Resultado esperado**: o que deve acontecer
- **Resultado real** e **Status**: preencher ao executar (`PASS` / `FAIL` / `SKIP`)

## Bloco A — Card 0213: Edição de Rota-Base

### A-01 — Abrir form de edição com dados pré-preenchidos

**Pré-condição:** Existe pelo menos uma rota cadastrada com nome, motorista, passageiros, dias e horário.

**Passos:**
1. Navegar para a aba "Rotas" no portal.
2. Clicar em uma rota para abrir o painel de detalhe.
3. Clicar no botão "Editar".

**Resultado esperado:**
- O formulário de criação de rota é exibido com todos os campos pré-preenchidos:
  - Nome da rota
  - Motorista selecionado
  - Passageiros selecionados (chip por passageiro)
  - Dias de operação marcados
  - Horário de partida
  - Nome e endereço do destino final
- O título exibe "Editar Rota" (não "Criar Nova Rota").
- O botão de confirmação exibe "Salvar Alterações" (não "Confirmar Rota").

**Passos:**

### C-04 — Dashboard mostra snackbar e mantém zeros quando o backend falha

**Pré-condição:** Backend indisponível (ex: desligar a VPN que dá acesso ao DEV, ou usar API URL errada).

**Passos:**
1. Configurar o app para apontar para uma URL inválida:
   ```
   flutter run -d "<device>" --dart-define=VANRIDES_API_BASE_URL=https://api-invalida.vanrides.test
   ```
2. Fazer login no portal (o login pode falhar também — nesse caso, verificar via teste automático).
3. Se conseguir chegar ao dashboard, observar o comportamento.

**Resultado esperado:**
- Um snackbar aparece com mensagem indicando falha ao carregar métricas.
- Os cards exibem zeros (não travam ou mostram tela de erro).
- O portal permanece navegável (menu lateral funciona).

**Observação:** Este caso é coberto pelo teste automático `admin_dashboard_screen_test.dart` (cenário `_FailingGateway`). Marcar como verificado via teste automático se o smoke manual não for viável.
